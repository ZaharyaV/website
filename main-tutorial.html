This is tutorial 2 (part 1) of my neurodivergence-friendly tutorial series for Scrivener 3. It’s intended for people who are new to Scrivener, as well as people who are already familiar with it, as it covers the major features in quite a bit of detail.

Important note: All my tutorials are based on Scrivener for MacOS! Though minor, there are some differences between Scrivener 3 for Windows vs for MacOS, so you may notice a few small discrepancies if you use Scrivener with Windows.
Further, all tutorials are based on my own personal workflow, and all screenshots are from my personal files, so please don’t distribute those elsewhere. My workflow is not universal (duh), and if you use certain features differently that doesn’t mean one of us is doing it wrong. You do you!

Main Tutorial (Part 1)

Alright, so you’ve just installed Scrivener, or you know Scrivener but want to learn more about it – so we’ll pretend you just installed it for a second. Yes? Yes.

As could be expected, you have to create a new project first of all – and seeing that you’re here, you’ve already skipped over the Getting Started options that pop up first. So you’re probably looking at this:

Personally I recommend to pick a suitable Project Template for your needs. Are you writing Fiction? Non-fiction? Scripts? The choice of project template matters because each project template comes with a particular preset of root-folder structure, section types, and compile formats that suit the needs of whichever type of document you’re writing, as well as potentially certain types of prepared Document Templates (e.g. Character/Place sheets for Novels vs Style Guidelines for Research Proposals). You can adjust all that in the settings, but that’s not part of this tutorial here. [Further information about all these things can be found in the continuing tutorials.]

Making a bold assumption here, most people reading this are probably fiction writers; so we’ll go with Novel with Parts here. Am I biased because NwP is my favourite? Maybe.

“But V, my story doesn’t have Parts!”
Yeah okay, I mean– alright, fine; if you are writing a story that very definitely does not have Parts, just ignore my yammering and choose Novel.

Once you have picked a project template, it will ask you to save the project-file somewhere on your computer; give it a file-name and save it wherever you save your writing documents. Scrivener will then open the brand new project, and you’ll see something like this:

Let’s have a look at the main elements of the interface: Spanning the top you have the Toolbar, which we’ll get into in detail towards the end of this tutorial. Then, on the left you have the Binder, in the middle there’s the Format Bar with the Editor(s) right below, and on the right you have the Inspector open on the first tab. [Note that this arrangement is simply the default layout and there are myriad options to customise the interface (beyond what I mention here)! ]

Well then, let’s get into it!


The Binder

The Binder on the left is where your folders and text files are organised. As already mentioned, I use Novel with Parts (NwP), so the basic preset structure inside the Manuscript folder matches that: First-level folders are Parts, second-level folders are Chapters, and the text files inside are Scenes. [From now on, if I say “file”, I am referring to these text files, not the .scriv Project file that sits on your desktop somewhere! ] You can also stack several files.

The NwP project template presets exemplary folders named Part and Chapter, but you can name your folders and files whatever you want. If you leave a folder or file unnamed, the Binder will show the first few words of either the text itself or, if there is one, the Synopsis – don’t worry we’ll get to that in a bit.
Here’s a closer look at an example from one of my long fics:

Generally, the idea is to do your actual writing in files (Scenes), but it is also possible to write directly in a folder. To start with, I’d recommend keeping your text in files though, since most preset export formats are set up with that assumption and text that sits directly in a folder might not show up on compile – but more on that later (much, much later).

So what exactly is inside a file? I generally write one-scene-per-file in my manuscript; having multiple scenes in the same file only works with short one-shots with tiny scenes for me. But that’s just me – you can totally have several scenes in the same file if you want to – whatever works best for you in your specific project. 

Outside of the Manuscript, your files can contain anything you need them to – in my case it’s mostly notes. This includes Character and Place sheets, which have their own root-folders each in NwP projects; if you create a new file inside one of these root-folders, it will automatically match the preset Character and Place sketches. That’s because these preset Character sketches and Place sketches are Document Templates that are included in any of the Fiction-type Project Templates (Short Story, Novel, Novel with Parts).

[Other Project Templates may include other preset Document Templates, but in turn will not include these.]

Status and Labels

Both folders and files can have a Status, as well as a Label. You can set them in their respective drop-down menus in the bottom-right corner of the interface, or via right-click  on the folder(s)/file(s) in the Binder itself.

The Status generally refers to, well, the status of the thing – Default options include In progress, First draft, Revised draft etc. Default options for Labels are 6 basic colours.

Both Label and Status options are customisable! Simply click Edit to rename, add, edit or remove options.

“But why would I do that?” – So glad you asked!

For example, in the screenshots above you’ll see that the icons of all the folders and files have different colours in my Binder; that’s because I adjusted my settings so that folders and files show the Label colour. In my case, the Label is (primarily) tied to the POV; that way I can see at a glance how frequent any given POV is, and how they’re roughly distributed. For fics that I started posting before they were complete, I also turned a few key Statuses into Labels, to easily see what’s posted. But that’s totally individual and up to you if and how you’d wanna use labels. I just like it colourful.

Besides that, you can Filter by Status and Label in the Project Search, and make (automated) Collections based on your search criteria. But that’s a topic for the Extended Tutorial. Anyway, where were we? Right.

What you select in the Binder is what will be shown in the Editor; for example, if you select the whole Manuscript root-folder, all folders and files contained within the Manuscript will be shown in the Editor. Alternatively, you could select a part folder, a chapter folder, or a single scene — depends on what you wanna work on etc. If you select a folder (on any level) or multiple files, all files within the folder or selection will be shown in a continuous scroll, separated by dashed lines. This is called a Scrivening. The word count at the bottom of the Editor indicates the total word count of the selected Scrivening (or file if you only selected one).

You can also import external files by simply drag-and-dropping them into the Binder. For example, you could import a PDF of a paper into the Research folder so you have it easily accessible while you work.


The Editor

The Editor in the middle has three main view modes: Scrivenings mode (shown in the screenshot above), Corkboard mode, and Outline mode. To switch, click the respective symbol right of the Quick Search bar in the middle.

So far, all the screenshots showed the Editor(s) in Scrivening mode – the mode that displays the content/text of whatever you have selected in the Binder. [Images of the other two modes are coming up further down.]

Above the Editor(s) is the Format Bar, which is pretty much the same as most format bars; you can change your font, font size, colour, highlight colour, alignment – and so on and so forth. Note that the appearance of your text in the Editor is not necessarily the same as the output when you compile the project! [Further details in the Compile tutorial.]

There are a couple other options for the Editor (including Typewriter mode, Focus, and Composition mode); they are covered in the Extended Tutorial.
